# Інструкція з резервного копіювання проєкту

## Призначення
Цей документ описує стратегію резервного копіювання RiotApiProject, процедури створення резервних копій, перевірки їх цілісності та порядок відновлення у разі втрати даних або збою.

## Стратегія резервного копіювання

### Типи резервних копій
Для проєкту доцільно використовувати такі типи резервного копіювання:

- **Повна резервна копія** — повне збереження бази даних, конфігурацій і критично важливих файлів.
- **Інкрементальна резервна копія** — збереження лише тих даних, які змінилися з моменту останнього backup.
- **Диференціальна резервна копія** — збереження змін з моменту створення останньої повної резервної копії.

Для невеликого навчального проєкту основною є **повна резервна копія**, оскільки вона є найпростішою в реалізації та відновленні.

### Частота створення резервних копій
Рекомендована частота:

- база даних — перед кожним оновленням і не рідше одного разу на добу;
- конфігураційні файли — перед кожною зміною;
- jar-файл або зібрана версія застосунку — перед оновленням;
- користувацькі дані та логи — регулярно, залежно від активності системи.

### Зберігання та ротація копій
Резервні копії рекомендується зберігати:
- локально в окремій папці;
- на зовнішньому носії або в окремому захищеному сховищі;
- з розділенням за датами створення.

Приклад структури:
- `backup/database/`
- `backup/config/`
- `backup/build/`
- `backup/logs/`

Рекомендується зберігати:
- останні 7 щоденних копій;
- останні 4 тижневі копії;
- останні 3 місячні копії.

## Процедура резервного копіювання

### Резервне копіювання бази даних
Для PostgreSQL можна використати команду:

```bash
pg_dump -U riot_user -d riot_api_project > backup/database/riot_api_project_backup.sql
```

### Резервне копіювання конфігурацій
Для збереження конфігураційних файлів можна використати:

```bat
copy src\main\resources\application.properties backup\config\application.properties.bak
```

### Резервне копіювання jar-файлу
Для збереження зібраної версії застосунку:

```bat
copy target\RiotApiPractice-1.0-SNAPSHOT.jar backup\build\RiotApiPractice-1.0-SNAPSHOT.jar.bak
```

### Резервне копіювання користувацьких даних
Якщо в майбутньому проєкт буде зберігати окремі користувацькі файли, їх потрібно копіювати в окрему директорію backup.

Приклад:
```bat
xcopy data backup\data\ /E /I /Y
```

### Резервне копіювання логів системи
Якщо застосунок веде окремі log-файли, їх також потрібно копіювати:

```bat
xcopy logs backup\logs\ /E /I /Y
```

## Перевірка цілісності резервних копій
Після створення резервної копії потрібно перевірити:

- чи файл резервної копії реально створився;
- чи його розмір більше нуля;
- чи файл відкривається без пошкоджень;
- чи SQL backup містить коректні команди створення та вставки;
- чи jar-файл не пошкоджений;
- чи конфігураційні файли скопійовані повністю.

Для бази даних також бажано періодично виконувати тестове відновлення на окремому середовищі.

## Автоматизація процесу резервного копіювання
Резервне копіювання можна автоматизувати за допомогою `.bat` або `.sh` скриптів, а запускати їх через:

- Планувальник завдань Windows;
- cron на Linux/macOS.

Приклад простого Windows-скрипта для backup:

```bat
@echo off
if not exist backup mkdir backup
if not exist backup\database mkdir backup\database
if not exist backup\config mkdir backup\config
if not exist backup\build mkdir backup\build

pg_dump -U riot_user -d riot_api_project > backup\database\riot_api_project_backup.sql
copy src\main\resources\application.properties backup\config\application.properties.bak
copy target\RiotApiPractice-1.0-SNAPSHOT.jar backup\build\RiotApiPractice-1.0-SNAPSHOT.jar.bak

echo Backup completed.
pause
```

## Процедура відновлення з резервних копій

### Повне відновлення системи
Для повного відновлення потрібно:

1. Відновити базу даних:
```bash
psql -U riot_user -d riot_api_project < backup/database/riot_api_project_backup.sql
```

2. Відновити конфігурацію:
```bat
copy backup\config\application.properties.bak src\main\resources\application.properties
```

3. Відновити jar-файл:
```bat
copy backup\build\RiotApiPractice-1.0-SNAPSHOT.jar.bak target\RiotApiPractice-1.0-SNAPSHOT.jar
```

4. Запустити застосунок повторно:
```bash
java -jar target\RiotApiPractice-1.0-SNAPSHOT.jar
```

### Вибіркове відновлення даних
Якщо потрібно відновити лише окрему частину даних:
- відновлюється тільки конфігурація;
- або тільки база даних;
- або тільки jar-файл;
- або окремі користувацькі файли / логи.

Такий підхід зручний, якщо проблема торкнулась лише однієї частини системи.

### Тестування відновлення
Після відновлення потрібно перевірити:

- чи застосунок запускається без помилок;
- чи є підключення до PostgreSQL;
- чи доступні потрібні дані;
- чи відповідає застосунок на HTTP-запити;
- чи конфігурація застосована коректно.

## Висновок
Резервне копіювання є важливою частиною підтримки проєкту. Регулярне створення резервних копій бази даних, конфігурацій і зібраної версії застосунку зменшує ризик втрати даних і спрощує відновлення системи після збоїв або невдалих оновлень.
