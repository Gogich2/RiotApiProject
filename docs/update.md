# Інструкція з оновлення проєкту

## Призначення
Цей документ описує процедуру оновлення RiotApiProject у production-середовищі на Windows.

## Підготовка до оновлення

### Створення резервних копій

#### Backup бази даних
```bash
pg_dump -U riot_user -d riot_api_project > riot_api_project_backup.sql
```

#### Збереження поточного jar-файлу
```bat
copy target\RiotApiPractice-1.0-SNAPSHOT.jar target\RiotApiPractice-1.0-SNAPSHOT.jar.bak
```

#### Збереження конфігурації
```bat
copy src\main\resources\application.properties src\main\resources\application.properties.bak
```

### Перевірка сумісності
Перед оновленням потрібно перевірити:
- чи нова версія використовує ту саму версію Java;
- чи сумісні зміни з поточною схемою БД;
- чи не змінився формат конфігурації.

### Планування простою
Якщо оновлення включає зміну структури БД або конфігурації, бажано виконувати його в період мінімального навантаження.

## Процес оновлення

### Зупинка поточної версії
Якщо застосунок запущений у відкритому вікні консолі, потрібно зупинити його вручну через `Ctrl + C`.

### Оновлення коду
```bash
git pull origin main
```

Або, якщо потрібна конкретна версія:

```bash
git checkout <tag_or_commit>
```

### Збірка нової версії
```bash
mvn clean package
```

### Оновлення конфігурації
За потреби потрібно оновити:
- `application.properties`;
- параметри підключення до БД;
- змінні середовища.

### Міграція даних
Якщо зміни торкаються БД, потрібно:
- перевірити, що `spring.jpa.hibernate.ddl-auto` виставлено коректно;
- виконати оновлення схеми;
- переконатися, що нова версія сумісна з уже наявними даними.

### Запуск нової версії
```bash
java -jar target\RiotApiPractice-1.0-SNAPSHOT.jar
```

## Перевірка після оновлення

### Перевірка запуску
Потрібно переконатися, що застосунок стартував без помилок.

### Перевірка HTTP-відповіді
```bash
curl http://localhost:8080
```

### Перевірка PostgreSQL
Потрібно переконатися, що:
- у консолі немає помилок підключення;
- застосунок коректно працює з даними.

## Можливі проблеми
Типові проблеми після оновлення:
- застосунок не стартує через неправильні налаштування БД;
- помилка версії Java;
- конфлікт конфігурації;
- несумісність схеми БД.

## Процедура rollback

### Зупинка нової версії
Якщо застосунок запущений у консолі, потрібно зупинити його через `Ctrl + C`.

### Відновлення попереднього jar-файлу
```bat
copy target\RiotApiPractice-1.0-SNAPSHOT.jar.bak target\RiotApiPractice-1.0-SNAPSHOT.jar
```

### Відновлення конфігурації
```bat
copy src\main\resources\application.properties.bak src\main\resources\application.properties
```

### Відновлення бази даних
```bash
psql -U riot_user -d riot_api_project < riot_api_project_backup.sql
```

### Запуск попередньої версії
```bash
java -jar target\RiotApiPractice-1.0-SNAPSHOT.jar
```

## Висновок
Оновлення потрібно виконувати лише після створення резервних копій, перевірки сумісності та підготовки rollback-сценарію. Це зменшує ризик втрати даних і збоїв у роботі системи.
