# Налаштування лінтингу

## Обраний лінтер
Для проєкту було обрано **Checkstyle**.

## Причини вибору
Checkstyle добре підходить для Java-проєктів, які використовують Maven.  
Він дозволяє:
- контролювати єдиний стиль коду;
- знаходити типові помилки форматування;
- виявляти зайві імпорти;
- покращувати читабельність і підтримуваність коду;
- інтегрувати перевірку в процес збірки.

## Які аспекти якості коду важливі для проєкту
Для RiotApiProject найбільш важливими є:
- єдиний стиль коду;
- читабельність класів, методів і тестів;
- коректні імпорти;
- відступи та пробіли;
- уникнення зайвих або потенційно проблемних конструкцій.

## Базові правила
У проєкті налаштовано такі базові правила:
- заборона wildcard imports;
- заборона невикористаних import;
- обов’язкові фігурні дужки для блоків;
- перевірка пробілів і відступів;
- перевірка розділення порожніми рядками;
- перевірка назв класів, методів, полів і параметрів;
- перевірка максимальної довжини рядка.

## Конфігурація
Основний конфігураційний файл лінтера:
- `checkstyle.xml`

## Інструкція з запуску
Запуск перевірки виконується командою:

```bash
mvn checkstyle:checkstyle
```

Або разом із фазою збірки:

```bash
mvn validate
```

## Що перевіряється
Лінтер аналізує:
- основний код у `src/main/java`
- тестовий код у `src/test/java`

## Git hooks
Для автоматичної перевірки стилю коду перед комітом використовується pre-commit hook.

Hook запускає команду:

```bash
mvn checkstyle:check
```

Якщо Checkstyle знаходить порушення, коміт переривається.

Файли hook розміщені в:
- `docs/scripts/git-hooks/pre-commit`
- `docs/scripts/git-hooks/pre-commit.bat`

## Висновок
Використання Checkstyle у проєкті дозволяє підтримувати єдиний стиль коду, швидше знаходити типові помилки та спрощує подальший code review.
