# Генерація документації

## Обраний інструмент
Для автоматичної генерації документації в проєкті використовується **Javadoc**.

## Чому обрано Javadoc
Javadoc є стандартним інструментом документування для Java.  
Він дозволяє:
- документувати класи, інтерфейси та методи безпосередньо в коді;
- автоматично генерувати HTML-документацію;
- інтегрувати процес генерації у Maven-збірку;
- підтримувати документацію разом із розвитком проєкту.

## Запуск генерації документації
Для генерації документації потрібно виконати:

```bash
mvn javadoc:javadoc
```

## Результат генерації
Згенерована документація буде розміщена в папці:

```text
target/site/apidocs
```

## Генерація документації через Maven build
Також можна використовувати:

```bash
mvn clean package
mvn site
```

або окремо:

```bash
mvn javadoc:javadoc
```

## Що потрібно документувати
У проєкті потрібно документувати:
- публічні класи;
- публічні інтерфейси;
- публічні методи;
- DTO, якщо вони є частиною зовнішнього API;
- бізнес-логіку в сервісах;
- складні алгоритми та нетривіальні рішення;
- взаємодію між компонентами.

## Формат документування
Для документування використовується формат Javadoc:

```java
/**
 * Короткий опис класу або методу.
 *
 * @param parameter опис параметра
 * @return опис результату
 * @throws ExceptionType опис винятку
 */
```
## Правила документування коду

У проєкті для документування використовується **Javadoc**.

Потрібно документувати:
- усі публічні класи;
- публічні інтерфейси;
- публічні методи;
- сервіси з бізнес-логікою;
- складні алгоритми;
- взаємодію між компонентами.

Документація має містити:
- короткий опис призначення;
- опис параметрів через `@param`;
- опис результату через `@return`;
- опис винятків через `@throws`, якщо це потрібно.

При внесенні нових змін у код документацію потрібно оновлювати разом із кодом.

## Додатково
Для API-документації у проєкті може використовуватись OpenAPI / Swagger, якщо API розширюється або потребує окремого опису ендпоінтів.
