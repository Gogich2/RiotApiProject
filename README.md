# RiotApiProject

## Опис проєкту
**RiotApiProject** , це бакалаврський проєкт, який знаходиться в процесі розробки.  
Його основна мета , отримання, обробка та збереження даних з **Riot API** для подальшого аналізу та використання в інформаційній системі.

На поточному етапі проєкт зосереджений на серверній частині: отриманні даних про гравців, матчі та пов’язані сутності, їх обробці та збереженні в базі даних.

У подальшому до проєкту планується додати **вебсайт-частину**, яка буде відображати вже оброблену інформацію у зручному для користувача вигляді.

## Мета проєкту
Метою проєкту є створення системи для:
- отримання даних з Riot API;
- автоматизованої обробки та структуризації цих даних;
- збереження інформації у базі даних;
- подальшого виведення результатів через вебінтерфейс.

## Поточний стан
Проєкт **ще не завершений** і активно розробляється.  
Наразі реалізовується та вдосконалюється backend-частина застосунку.  
Frontend / вебінтерфейс планується додати на наступних етапах розробки.

## Перевірка встановленого середовища
Перед запуском варто перевірити, що Java та Maven встановлені коректно:

```bash
java -version
mvn -version
```

Також потрібно переконатися, що PostgreSQL встановлений і запущений.

## Налаштування бази даних

### Створення бази даних
Після встановлення PostgreSQL потрібно створити базу даних:

```sql
CREATE DATABASE riot_api_project;
```

### Створення користувача
```sql
CREATE USER riot_user WITH PASSWORD 'strong_password';
GRANT ALL PRIVILEGES ON DATABASE riot_api_project TO riot_user;
```

## Налаштування конфігурації
У файлі `src/main/resources/application.properties` потрібно вказати параметри підключення до бази даних.

Приклад:

```properties
spring.datasource.url=jdbc:postgresql://localhost:5432/riot_api_project
spring.datasource.username=riot_user
spring.datasource.password=strong_password
spring.datasource.driver-class-name=org.postgresql.Driver
spring.jpa.hibernate.ddl-auto=update
spring.jpa.show-sql=true
```

## Документування коду
У проєкті для документування використовується **Javadoc**.

Усі учасники проєкту повинні дотримуватись таких правил:

- документувати всі публічні класи;
- документувати всі публічні інтерфейси;
- документувати всі публічні методи;
- документувати сервіси, що містять бізнес-логіку;
- додавати пояснення до складних алгоритмів і нетривіальних рішень;
- оновлювати документацію разом зі змінами в коді.

Javadoc-коментарі мають містити:
- короткий опис призначення класу або методу;
- `@param` для опису параметрів;
- `@return` для опису результату;
- `@throws` для опису можливих винятків, якщо це потрібно.

Приклад оформлення:

```java
/**
 * Виконує обробку матчів для заданого гравця.
 *
 * @param puuid унікальний ідентифікатор гравця
 * @param limit максимальна кількість матчів для обробки
 * @return результат виконання операції
 */
```

## Генерація документації
Для автоматичної генерації документації використовується **Javadoc** через Maven.

Команда для генерації:

```bash
mvn javadoc:javadoc
```

Згенерована документація буде доступна в папці:

```text
target/site/apidocs
```

## Документація

- `docs/generate_docs.md` , інструкція з генерації документації.
